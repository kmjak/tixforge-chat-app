# プロジェクト概要

## サービスの目的
仕事・リアルの友人・ゲーム・推し活など、場面ごとに別々のチャットアプリを入れたり、アカウントを作り分けたりしている人向けの、リアルタイムチャットアプリ。
1 つのアカウントで複数のプロフィールを作り、サーバーや友人ごとにどのプロフィールを使うかを設定できるようにする。これにより、1 つのアプリで場面を切り替えずにやり取りできるようにする。

## 主要なドメイン概念
- **アカウント**：ログインの単位。1 人に 1 つ。メールアドレスとパスワードで登録する。アカウントの id は、ほかのアカウントに見せない。
- **プロフィール**：アカウントの下に複数作れる「顔」（5 個まで）。name・bio を持つ（avatar は MVP 外）。アカウントごとにデフォルトプロフィールを 1 つ持つ。デフォルトのプロフィールと、使用中（サーバー・フレンド・グループ DM に割り当て済み）のプロフィールは削除できない。
- **サーバー**：Discord のようなコミュニティの単位。中にチャンネルを持つ。招待リンクで参加し、参加するときに、そのサーバーで使うプロフィールを選ぶ。作った人がオーナーになる。
- **チャンネル**：サーバーの中の会話の場。サーバーを作ると既定のチャンネル（`一般`）ができ、これは削除できない。カテゴリでまとめられる。
- **フレンド**：アカウント同士の関係。同じサーバーのメンバーへの申請か、フレンドリンクでフレンドになる。各自が相手ごとに、見せるプロフィールを選べる。相手からは、自分に割り当てられたプロフィールしか見えない。同じ人が別のプロフィールを持っていることも分からない。
- **DM**：フレンドとの 1 対 1 の会話。そのフレンドに割り当てたプロフィールを使う。フレンドでない相手とは DM できない。
- **グループ DM**：最大 10 人の会話。メンバーが自分のフレンドを招待し、招待された人は承認するときに、そのグループ DM で使うプロフィールを選ぶ。
- **メッセージ**：チャンネル・DM・グループ DM に投稿するテキスト。リアルタイムに届く。送り手は、その場で使っている今のプロフィールで表示される。

## アーキテクチャ／ディレクトリ構成
pnpm workspaces の monorepo。クライアントは Web のみ。

- `apps/web/` — Next.js。画面。Better Auth のクライアントから server の認証 API を使う。
- `apps/server/` — Hono。REST API・WebSocket（リアルタイム配信）・認証（Better Auth）。常駐するサーバーとして動かす（サーバーレス環境では WebSocket の接続を保てないため、Next.js とは分ける）。DB に接続するのは server だけ。
- `packages/db/` — Drizzle のスキーマ・マイグレーション。
- `packages/shared/` — web と server で共有する型・バリデーション。

## 技術スタック
- 言語：TypeScript
- フロントエンド：Next.js
- バックエンド：Hono（Node.js）
- リアルタイム通信：WebSocket
- DB：Neon（Postgres）＋ Drizzle ORM
- 認証：Better Auth（セッションを DB に保存）
- lint・フォーマッタ：Biome
- テスト：Jest
- パッケージマネージャ：pnpm（Node.js のバージョンは `.nvmrc` で固定）

## 開発・テストの実行方法
セットアップの手順は README を参照。コマンドはすべてリポジトリのルートで実行する。

- `pnpm dev` — web（:3000）と server（:3001）を同時に開発起動
- `pnpm typecheck` — 全パッケージの型チェック
- `pnpm lint` — Biome で lint とフォーマットを検査（書き換えない）
- `pnpm format` — Biome で自動修正
- `pnpm test` — 全パッケージのテスト（Jest）
- `pnpm build` — web と server のビルド

検証コマンド（`.tixforge/config.yml` の `commands`）には、typecheck・lint・test・build をこの順で登録している。
