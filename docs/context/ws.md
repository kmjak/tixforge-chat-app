# WebSocket（リアルタイム配信）

server（Hono）からブラウザへ、イベントをリアルタイムに届ける仕組み。ログイン済みのブラウザは、server と 1 本の WebSocket の接続を持ち、参加しているすべての「部屋」のイベントを、この 1 本で受け取る（GT-000013）。API のパスは [uri.md](uri.md)、画面のパスは [routes.md](routes.md) にある。

## 接続

| 項目 | 内容 |
|------|------|
| 状態 | 実装済み（GT-000013） |
| 接続先 | `GET /api/ws`（server の origin。`http` は `ws`、`https` は `wss` にする。例：`ws://localhost:3001/api/ws`） |
| 認証が必要か | 必要。API と同じ Better Auth のセッションの cookie で確かめる（[ログインの確認](uri.md#ログインの確認)） |
| Origin | web の origin（server の環境変数 `WEB_ORIGIN`）だけを受け付ける |
| 向き | server → ブラウザだけ。ブラウザから送ったものは使わない（無視する）。受け取るメッセージは 4096 バイトまで（超えると server が `1009` で閉じる） |
| 呼び出し元 URL | ログイン後のすべての画面（`/`・`/sign-in`・`/sign-up` 以外。`apps/web/app/components/realtime-provider.tsx`） |

### 接続できないとき（upgrade の前に返す HTTP のステータス）
- `401`：セッションが無い・無効・期限切れ
- `403`：`Origin` が web の origin でない（WebSocket には CORS が効かないので、他のサイトがログイン中の cookie で接続するのを、ここで防ぐ）

### 接続を閉じるとき
| コード | 意味 | ブラウザの動き |
|--------|------|----------------|
| `4001` | セッションが無効になった（サインアウト・期限切れ・失効） | 再接続しない。画面を読み込み直す（proxy がサインインの画面へ移す） |
| そのほか（server の再起動・回線の切断など） | — | 自動で再接続する。待ち時間は 1 秒から倍にし、30 秒まで。つながったら 1 秒に戻す |

- `/api/auth/*` への POST（サインアウト・セッションの失効・パスワードの変更など。サインアップ・サインインを除く）が成功したら、server はそのアカウントの接続のセッションをその場で確かめ直し、無効になったものをすぐに `4001` で閉じる。
- つながらずに閉じたとき（未ログインの `401` も、ブラウザにはコードで区別できずにこう見える）は、ブラウザが [`GET /api/auth/get-session`](uri/get-api-auth-get-session.md) でセッションを確かめる。無効なら `4001` と同じく再接続せずに読み込み直し、確かめられない（server に届かない）なら再接続を続ける。
- 再接続を待っている間は、ログイン後の画面の上に「接続が切れました。再接続しています…」と出す。

### 生存確認
- server は 30 秒ごとに ping を送り、前回の ping に pong が返っていない接続を切る（ブラウザは ping に自動で pong を返す）。
- 同じタイミングで、各接続のセッションがまだ有効かを確かめ直し、無効なら `4001` で閉じる（DB の一時的な失敗などで確かめられなかったセッションは、その回は閉じない）。

## 部屋（イベントの届け先）
server の処理は、部屋を指定してイベントを送る。**届け先は、送るたびに DB からその部屋の今の参加者を決める**ので、接続した後の参加・退出・チャンネルの作成・削除は、次に送るイベントからすぐに反映される。参加者でない接続には届かない。同じアカウントの接続（複数のタブ・端末）すべてに届く。

| 部屋 | 表し方 | 参加者 | 状態 |
|------|--------|--------|------|
| チャンネル | `{ "type": "channel", "id": "<チャンネルの id>" }` | 削除されていないチャンネルの、サーバーの今のメンバー（`server_members.left_at` が null） | 実装済み（GT-000013） |
| DM | — | — | 予定（GT-000017） |
| グループ DM | — | — | 予定（GT-000018） |

- 配信の仕組みは server の 1 台のメモリで持つ（複数台に広げるときは Redis などで配る。MVP の対象外）。

## イベントの形式
イベントは JSON の文字列で、1 つのメッセージに 1 つ。型は `packages/shared` の `WsServerEvent`。

| フィールド | 型 | 必須 | 説明 |
|------------|----|------|------|
| `type` | string | はい | イベントの種類（下の一覧） |
| `room` | `Room` | 部屋に送るイベントだけ | 届け先の部屋（上の「部屋」の表し方） |
| `data` | イベントごとに決める | 部屋に送るイベントだけ | イベントの中身 |

### イベントの一覧
| `type` | 部屋 | `data` | 送るとき | 状態 |
|--------|------|--------|----------|------|
| `ready` | なし | なし | 接続できたとき（最初に 1 回） | 実装済み（GT-000013） |

```json
{ "type": "ready" }
```

## 追記の決まり
- **新しいイベントを送るチケットは、「イベントの一覧」に行を足し、`data` の型を表で書く**（`packages/shared` の型も足す）。
- **新しい種類の部屋を足すチケットは、「部屋」の表に、表し方と参加者の決め方を書く**（`packages/db` の `listRoomMemberIds` に足す）。
- 状態の書き方は [uri.md](uri.md#状態の書き方) と同じ。
